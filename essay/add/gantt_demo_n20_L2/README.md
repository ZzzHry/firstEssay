## 实际求解与检查

在独立进程中分别运行现有整线分解框架和 Compact CPLEX，名义预算均为 30 s。两者均证明整数最优利润为 **132.58**（求解器浮点容差意义下）；本图采用分解算法返回的方案。CPLEX 22.1.1.0、单线程、随机种子 11，设置可在原始日志中核查。数值政策保存在 `cg_result.json` 中。

该方案执行 14/20 个任务，使用人工 3、机器人 2。两个算法可能返回不同站号的多重最优解，本图只画一份真实分解解。此演示不用于比较算法速度。

H 为人工，R 为机器人，J 为协作。J 占用两类配置资源，但任务时间仅计一次。未选任务为 L1 的 T5、T8 和 L2 的 T14、T15、T16、T19。模型允许前面存在未启用站点，因此保留原站号，没有为了图面而重新分配任务。

## 如何理解横轴与顺序

模型直接决定任务选择、站点分配和执行模式，**没有优化任务开始时刻**。绘图时对每个站内的已选任务作拓扑排序，以数字任务编号打破并列，再按实际模式时长顺序放置任务。得到的是一份符合现有站内优先关系及节拍的展示顺序，并非唯一或额外优化过的顺序。

横轴是各工作站各自独立的节拍内时间；不同站点处于流水线的不同阶段。这不是同一件产品从入口到出口的绝对时间轴，不能据此比较跨站任务的开始时刻或声称优化了总工期。跨站前驱关系由站点序号检查；同站前驱关系另外检查先后结束/开始时刻。

## 证据与复现

- `cg_result.json`、`compact_result.json`：实际求解输出，保留最优性状态和上下界。
- `logs_cg/`、`logs_compact/`：CPLEX 原始日志。
- `schedule.csv`：逐任务线、站、模式、顺序及恢复的开始/结束时间。
- `station_summary.csv`：全部工作站（含空站）的任务、时间、资源和疲劳。
- `verification.json`：两份整数 witness 均通过数据级检查和原 Compact 模型全部约束检查；另外检查画图恢复的时间与顺序。
- `provenance.json`：求解基线版本、环境、冻结输入与相关源码 SHA-256。
- `SHA256SUMS.txt`：交付文件哈希，不包含清单自身。
