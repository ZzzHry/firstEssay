# P0：资源档位查询价值诊断

日期：2026-11-11。结论：**P0 PASS，可进入 P1 安全查询接口；尚不具备直接训练 RL 的证据。**

本轮实际读取 stage13 的四个分解完整结果及对应 Compact 输入，重新核验输入、证据和源码哈希，以独立的“剩余容量递归”重建资源组合，不调用生产 DP，不调用优化器。历史算例没有重新求解。本报告中的求解时间均来自历史记录，不能称本轮新性能实验。

- 对 272 个历史文件建立只读哈希索引，包括日志和批次元数据。日志索引不是重新运行原生求解器。
- 运行环境：Python 3.10.11、PuLP 3.3.2；通过项目加载器读取 CPLEX API 22.1.1.0。未调用 optimize，许可证实际求解测试 NOT RUN。

实际验证：每个 CG 退出列和最终整数 witness 的原始数据可行性；49 次档位查询的合法域、原生状态及局部列；逐步账本与最终保存账本完全相等；逐查询 upper_path 与独立递归最优上界相符；每个重建整数组合均通过原始约束检查；每个已记录 profile_account 的 LB/UB 与重建值一致。

本轮重放依赖历史原生求解证书的状态/界契约，不是严格有理认证。没有重新运行完整 CG 定价 Oracle、Compact 或独立列 IP 求解；这些不计为本轮通过。P1 仍须执行完整小例安全回归。

seed32/33 的 cg_lp_optimal 原生标记为 false，算法因整数 witness 与有效界闭合而提前完成。可说原整数问题已证最优，不能改写为其 CG 已按常规 RC 终止条件标记 LP 最优。

## 3. seed34：缺了什么列

最终 witness 使用 H=10、R=10。每线目标档位与入口列池对照：

|线|最终 (H,R)|最终线利润|入口有该档位列吗？|
|---|---|---:|---|
|L1|(1,2)|165.76|没有|
|L2|(1,2)|163.85|没有|
|L3|(2,2)|216.04|没有|
|L4|(2,1)|101.53|有，利润已相同|
|L5|(2,2)|176.23|没有|
|L6|(2,1)|186.57|有，利润已相同|

资源档账本共 486 个计数对，入口仅 27 档有列。486 中包含尚未知或真实不可行的档位，不能称其余 459 档都应补齐。

独立递归给出入口列池的整数组合最优值为 980.20（每档保留最高利润，对仅按资源耦合的整数主问题等价），因此**入口池无法组合出利润 1009.98 的任何方案**，不需要另调用求解器确认这一点。最终 witness 的四个缺失档位解释了这一缺口；尚不能断言它们分别是完整列域所有最优解必需的档位，因为可能存在另一份同目标最优方案。

## 4. seed34：31 次查询分别做了什么

|步骤|查询|查询后 LB|查询后 UB|历史 worker 相对时刻（秒）|主要作用|
|---|---|---:|---:|---:|---|
|0|补全入口|980.20|1047.980870|65.975|已可行，但 Gap 67.780870|
|1|L1(1,2)|1000.22|1043.202326|67.966|LB +20.02，新增必要档位|
|4|L2(1,2)|1000.22|1041.715660|72.487|补入最终 witness 使用的档位；即时 LB 不变|
|10|L3(2,2)|1006.02|1033.140403|82.786|LB +5.80；该次 PP 仍为 time_limit|
|15|L5(2,2)|1009.98|1027.13|91.658|LB +3.96，达到最终已证最优值；该次仍未证局部最优|
|26|L5(2,2)重复|1009.98|1011.871360|121.296|认证收紧；全局 UB 下降 4.60|
|31|L3(2,2)重复|1009.98|1009.98|144.155|全局界最终闭合|

完整 31 行见 queries.csv。共有 21 个不同档位，16 次局部最优、14 次 time_limit、1 次局部不可行。最大化 PP 的限时 incumbent 只贡献局部可行列；有效上界来自保存的原生 Best Bound 契约，二者分别处理。

- LB 真正提高的只有第 1、10、15 次，累计 +29.78。
- 有效全局 UB 下降 26 次，累计下降 38.000870。
- 第 13、17、19、22、25 次没有即时全局 LB/UB 改善；不能直接称为无用，可能更新替代组合的局部证据。
- 从首次记录最优利润（第15步）到证明闭合，约 52.50 秒。后半段重点是证明，并非继续找更高利润。
- L2 档在第4步补入而 LB 不变，最终又被最优 witness 使用，说明单步 LB 奖励会漏掉部分组合价值。它支持设计兼容性特征；尚不能单凭这条轨迹证明 PPO 优于 bandit。

## 5. 80/2：已有档位内部的质量问题

入口共 112 个计数对，仅 5 档有列。最终 witness 的 L1(1,2)、L2(4,5) 两档均已存在，因此不能简单使用“是否新增档位”评价查询。

- L1(1,2)：入口列利润 94.34，最终列利润 187.15，提高 92.81。
- L2(4,5)：入口已有利润 382.38，最终没有提高。
- 第11次查询 L1(1,2) 为 time_limit，但返回可验证的更好列，使全局 LB 从 476.72 提至 569.53。
- 18 次查询中，11 次证明局部不可行，合计仅 1.57 秒；7 次 time_limit。删除这11次查询不等于能节省大量原生求解时间，也不能依据本次事后结果把这些档位预先屏蔽。
- 全局 UB 始终为 738.727116。此例预算内的已证状态仍为未完成。历史 Compact 的更好解/界必须保留，不能只展示本框架内部改善。

当前规则在一个并列乐观路径上依 line/index 决策，此例前10次查询集中在 L1 的低资源档位；这是一项可检查的规则局限，但尚无受控新顺序证据证明改变顺序会改善最终质量。

## 7. 是否进入 P1

**建议继续 P1，范围限于安全接口和规则原型。** 原因是观察到两种真实可操作目标：补齐组合需要的档位，以及改进同档位内的利润；seed34 还有明显的上界认证工作量。

P1 应能插入新查询选择器，默认规则与旧版一致；状态必须同时包含已有 witness、局部有效界、其他线的兼容性、剩余预算和尝试次数。保留当前完整档位域，不依据学习评分删档。

尚不能进入训练的原因：只有两个查询活跃历史案例；未测试不同顺序；没有新的分组数据集；没有策略环境的 Oracle/伪造拒绝回归。P2 仍需验证强规则是否已经足够。对于 CG 主导的大块难例，单独保留原生定价优化方向。
