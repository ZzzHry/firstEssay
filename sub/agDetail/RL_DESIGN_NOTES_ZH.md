# 面向整数最优证明的强化学习辅助整线列生成：组会设计说明

日期：2026-11-08。代码阅读基线：`fb2b971d`，分支 `codex/sub-line-decomposition`。

**本文件是研究设计，不是已完成的 RL 实验报告。** 本次未训练网络、未修改求解器、未重跑性能实验。数值均来自已封存结果；现有 `RL/adaptive_v1` 中的 adaptive 是手工规则，不是强化学习。

## 1. 建议与理由

第一版让 RL 控制 **Phase II 中是否尝试候选定价，以及候选价格和时间投入**；原价完整认证、整数可行性核验、资源档位完备化与有效界计算保留为确定性证明内核。学习的目标是端到端获得好整数解和有效证明的效率。

不建议第一步训练网络直接输出整线任务—站点—模式配置。局部可行域包含 AND、必拆、节拍、疲劳、模式及配置逻辑，直接构造需要复杂动作掩码和修复，训练难度高，难以隔离收益来源。当前 RMP 本身也很便宜，所以大规模候选集中的“选哪一列”未必是主要痛点。

整线分解已经降低跨站拼装难度，但把组合难度集中到每条线的定价 MILP。RL 不能消除该问题的最坏情形复杂度；它只能在给定实例分布上改善求解调用及后续搜索轨迹。最困难的一次原价认证仍可能决定总耗时。若控制层没有稳定收益，应转向原生定价加速或整数界，而不是扩大网络。

## 2. 当前算法究竟是什么

实际生产入口是 `sub/stage11/run_plan_v2.py → worker_v2.py → sub/stage9/balanced_bound.py`。核心包括整线两阶段 CG、受限整数主问题恢复，以及按需资源档位查询和二维资源 DP。它不是当前论文必须调用的 Branch-and-Price 搜索树。

一列是一条线所有工作站的完整可行任务配置。线内约束由列满足；主问题管理每线恰选一列及系统人工、机器人总量。设列利润、人工数和机器人数分别为 c_lp、h_lp、r_lp，主问题为：

```text
max Σ_l Σ_p c_lp λ_lp
s.t. Σ_p λ_lp = 1                         ∀l
     Σ_l Σ_p h_lp λ_lp ≤ H
     Σ_l Σ_p r_lp λ_lp ≤ R
     λ_lp ≥ 0                            LP
```

相应整数模型要求 λ 为整数。最大化问题的原价检验数为

`rc_lp = c_lp − π_H h_lp − π_R r_lp − σ_l`，其中 π_H、π_R ≥ 0，σ_l 自由。

RMP 的 LP 目标不能当整数 LB。整数 LB 必须来自原约束验证通过的方案；全列 LP 界或完整资源档位的界用于 UB。正整数间隙存在时，根 CG 不会自动证明 IP 最优。生产链的档位完备化仍然有作用，不能在 RL 比较中悄悄删除。

## 3. 已有证据与适用边界

### 3.1 生产算法瓶颈

论文 `essay/myEssay/tables/formal.tex` 和 `iterations.tex` 的 6 个主实验：整线框架均证明整数最优，端到端约 19.36–182.69 秒；同协议 Compact 约 595.7 秒仍未证明。PP 原生时间 17.67–180.31 秒，占总时间约 91.3%–98.7%；RMP 原生时间均小于 0.01 秒。两者余项包含初始化、验证、模型更新、整数恢复、持久化等，不能全部算成 RMP。

这些是已选定实验族的结果，不是对任意大规模问题的普遍优势。紧资源场景中还有根 CG 未闭合、需要 31 次档位查询才完成整数证明的例子。训练与分析应区分“定价慢”和“整数补全慢”。

### 3.2 候选策略已显示状态相关取舍，但没有 RL 收益证据

来源：`RL/adaptive_v1/RESULTS.md`、`SUMMARY.md`、`LIMITATIONS.md`。同一实验引擎、同输入，每策略只跑一次，60 秒软算法预算；不是严格全进程 E2E，且该引擎没有生产资源档位 DP。

## 5. 第一版控制器的完整定义

### 5.1 决策时点

Phase I 保持原样。仅在 Phase II 中 RMP 已获可靠 primal/dual、整数恢复和有效界已更新后决策。上一次候选成功而尚未完成认证时，强制认证，不询问网络。已闭合真实整数 LB/有效 UB 时直接结束。

### 5.2 观察 o_t

- 全局：剩余预算比例、迭代阶段、当前及历史有效 UB、整数 LB、是否已有整数解、归一化 Gap、近期 LB/UB 改善及停滞。
- 对偶：原价 π_H、π_R、与上轮/参考价格的差异及振荡；归一化尺度由输入或训练集统计确定。
- 每线静态：任务数、站点数、AND 图密度、可用模式比例、节拍/疲劳的输入统计。
- 每线动态：最近精确定价时间、状态、RC、候选新增/重复率、列池规模、最近动作。
- 整数兼容性：列池内不同 (h,r) 档位数量及分布、稀缺资源的使用分布、受限 IP 是否有 witness、当前整数恢复结果。仅利用已知列池；不提前枚举完整档位利润。
- 历史与缺失掩码：最近 K 轮（建议 K=3 起步），没有 LB、无界或未运行项必须显式掩码，不能填零假装已知。

CPLEX 内部搜索状态没有完全观测，而且候选目标会影响重优化。因此严格说是部分可观测、持续时间可变的决策过程；不能仅凭一个特征向量就宣称完全 Markov。

### 5.3 七个离散动作

|动作|含义|
|---|---|
|CERTIFY|直接进入当前原价的全线精确定价|
|α=1、τ=0.5或2秒|短预算原价候选|
|α=0.5、τ=0.5或2秒|中度历史价格混合候选|
|α=0.25、τ=0.5或2秒|较强历史价格混合候选|

`tildeπ = α π_current + (1−α) π_ref`。π_ref 取截至当前已有完整认证中修复 UB 最好的那一轮；没有历史时用零价格，与已实现接口一致。σ_l 是每线常数，不影响该 PP 的最优配置，但原价 RC 核验必须扣除它。候选用原利润、相同合法整线域，不能更改物理约束。

τ 是每线候选求解器预算，不是硬实时保证。候选总投入先限制在 episode 预算的 20%；还须预留认证、整数恢复与持久化时间。动作掩码依据剩余预算裁定；可预计新增候选投入至少为 Lτ，必须避免线数增加时隐性多花预算。掩码使用保守建模/验证开销估计。预算数字是待试验起点，不是实测最优参数。

### 5.4 候选后的必经流程

1. 每个候选列逐项核验整线可行性和原始利润。
2. 使用**当前 RMP 原始对偶**重新计算 RC；当前版本仅加入新颖且 RC>ε 的列。
3. 有新列时重解 RMP、尝试整数恢复，之后强制完整原价认证；无新列则立即认证。
4. 有效认证失败、超时或异常时保持已有安全界，按既有安全终止/后处理规则处理，绝不冒充“没有改进列”。
5. 候选轮不能直接设置 LP 或 IP optimal。认证中的历史证明复用若启用，仍必须满足相同域、有效上界及完整块覆盖的原契约；第一版比较可统一关闭缓存以隔离控制收益，再做缓存消融。

某些非正 RC 列可能对整数组合有用，但本版不偷偷修改入池规则。若之后要引入专门的整数补充列，应定义独立动作/预算和回归测试。

## 6. 为什么仍然能够给出有效数学证明

当 RMP primal/dual 一致且每条线原价最优检验数 ρ_l 均已证得时，修复凸性对偶可得到

`UB_LP = D_RMP + Σ_l max(0, ρ_l)`。

理由：将每线自由凸性对偶 σ_l 提高 max(0,ρ_l)，使其覆盖该线所有缺失列；资源对偶不变，得到全列主问题对偶可行解。真实整数利润是 LB。只有 LB 与有效 UB 在原数值政策下闭合，或资源档位完备化给出相应证书，才能声明整数最优。

RL 改变查找列的路径，不参与修改这些不等式。即便策略很差，也只能导致慢、界差或超时，不能合法产生错误证明。这保证的是**输出证明的可靠性**；有限时间下不能保证每个输入完成整数证明。候选/认证交替、有界候选预算并不能代替必要的完整整数搜索或档位完备化。

候选 PP 的 incumbent 是该最大化 PP 的下界；混合价格下的最优值也不是当前原价的证明。截断 PP Best Bound 的一般非零价格认证扩展仍不纳入本设计。根 CG 收敛证明的是 Full-LP，仍不自动等于原 IP。

## 7. 奖励：对齐用户真正关心的整数结果

一个动作的反馈窗口包含候选、RMP/IP 恢复和它触发的强制认证；若尚有后续轮或档位补全，其影响通过整个 episode 回报反映。部署完整版本时，episode 必须包含相同的确定性档位后处理及结果持久化。只优化根 LP 的中间版本不能被宣称为完整生产算法收益。

建议先使用有界的“有效 Gap 面积 + 没有整数解的时间 + 总时间”代价。取从输入预先计算的固定正尺度 S（例如 `max(1, Σ_i max(0,任务回收收益_i))`；实现时按真实字段展开并核验，不能用事后最优值），若已有有限可靠 LB/UB，则

`g(t) = min(1, (UB(t)−LB(t))/S)`；否则 g(t)=1。

计算前检查 UB≥LB−原容差；超出容差的矛盾是错误，禁止通过截断隐藏。只有容差内微小负差可在记录残差后按零处理。训练过程中状态变化按已有验证完成事件更新，不能追溯奖励尚未持久化/核验的证明。

建议宏动作奖励：

`r_t = − (1/T) ∫[t,t+Δt] [w_time + w_gap g(u) + w_feas 1(没有已验证整数解)] du + b_proof 1(新获得完整终止证书)`。

初始化建议 `w_time=0.05, w_gap=1, w_feas=0.25, b_proof=0.2`，全部仅在训练/验证集调节。界缺失时给最坏归一化值，同时保留缺失掩码。不可行实例需分层报告，完整不可行证明才能获得终止奖励。新增列数和 RC 只作诊断，可在后续消融中测试辅助奖励，不能替代整数评价。

**防止奖励提前放弃：** 旧引擎可能在认证截断后提前返回，尚未用完总预算。若没有完整终止证书，训练回合不得因此免除剩余 Gap 代价。对停止时刻 t_stop 到 T，用最后有效界和 incumbent 状态补计 `−(T−t_stop)/T × [w_gap g_last + w_feas I(无整数解)]`，无需真实等待；总时间项仅计实际发生的时间。缺失证据或 solver error 不能获得证明奖励，另行记录错误，不能偷偷删掉失败 episode。这样避免策略学会通过触发失败来降低累计代价。

有限 episode 使用不再按决策步重复惩罚时间的回报（例如 γ=1，实际时间已进入奖励）；否则长求解步与短步的隐含折扣不同。先用完整回合回报/明确的 SMDP 价值估计，再考虑按实际持续时间折扣。不能直接套固定步长默认 γ 就声称时间一致。

## 8. 网络与训练方法

第一版采用小型共享每线编码器（例如两层 64 维 MLP），对线表示作 mean/max pooling，与全局特征拼接，输出 7 个动作概率及一个 value；动作掩码归一化后采样。该结构支持变线数且尊重线标签置换，不需要一开始上大型 GNN。3 轮历史作为起点；若隐藏状态影响明显，再增加 GRU，并与无历史模型消融。

PPO 是候选方案，理由是动作少、需要序列反馈、实现与审计较直接。必须与同动作空间的简单规则、监督选择器或上下文老虎机比较。若收益主要由当前状态决定且长期差异很小，老虎机可能更省样本；RL 不具优势就应报告这一结论。

训练使用真实求解器环境采集新轨迹。旧四策略日志只能做特征/奖励调试、监督预热或离线分析，不能直接当成 PPO 的当前策略样本。重放 JSON 不会恢复 CPLEX warm state；比较动作必须从同一前缀重新执行或采用预先规定的冷启动微基准，不能拿静态同一对偶就假设动态环境完全相同。

记录每次 native PP 的模型域、对偶、目标、状态、耗时、列、RC、LB/UB 来源；记录策略版本、随机种子和动作概率。记录训练 CPU/GPU 小时与部署推理开销，避免用昂贵训练成本换来几秒收益却不披露。

## 9. 数据集、防泄漏与公平评价

按**完整生成族/基础产品任务库**划分训练、验证、测试；同一任务库拆成不同线数、相近资源预算的输入不能跨集合。已看过的 seed32/34 等只用于开发。所有实例一次生成并冻结 JSON 和 SHA-256，不把生成器构造 witness 输入某个方法。

先建议 30 个新的开发实例（含易闭合、资源紧、整线 PP 难、整数间隙四类）检查动作是否有真实价值，再按资源成本扩大训练；最终测试至少 20–30 个独立实例、至少 3 个训练种子作为起点，实际样本量应依据方差与预算确定。先在 2/4/6 线、小到中等每线任务规模上训练；更大线数、每线任务数或资源比例作为 OOD，不能把“总任务数更大但每线不变”当成唯一泛化检验。

基线：完整生产框架、同新引擎关闭候选、short_raw、fixed、手工 adaptive、确定性价格稳定化/预算规则、同动作空间 bandit、PPO，以及最终阶段 Compact。缓存、warm start、档位 DP、数值容差均保持同配置；同机器、单线程、solver seed、总墙钟预算，计入特征、推理、建模、验证和必要持久化。候选开销和训练成本分别披露。

主要指标：已验证整数 LB、有效 UB/Gap、首个整数解时间、证明时间、预算内整数证明率、端到端时间及有效 Gap 曲线面积。超时作为删失/预算终止，不虚构成 3600 秒观测值。解释指标：PP 时间、认证轮、候选列数、档位查询数、CPLEX 状态及失败原因。

按完整实例配对分析，多训练种子的不确定性不能当成更多独立实例；报告胜/平/负、分位数和适当的配对区间，不只挑成功图。正式测试前锁定超参数和统计方案。

## 10. 消融与安全验收

机制消融：只有跳过/触发学习；再加 α；再加预算 τ；有无整数兼容性特征；整数奖励对比 LP-only 奖励；无历史对比有历史；bandit 对比 PPO；固定/统一 warm start 的同前缀微基准。不要把不同搜索轨迹的收益全归因于减少 Python 开销。

安全回归：小规模独立全列 Oracle、相同对偶下 RC 核验、人工变量/Phase I、整数 witness、对偶过期、未来参考价格、缺失线路认证、候选冒充证明、异常状态、预算截断及证书重放。对任何学习动作序列都执行相同检查。测试集外分布发生异常时回退确定性认证，界和状态仍须诚实保留。

**进入 RL 的门槛**：新开发集上固定动作之间确有稳定互补、状态能解释选择价值，并且这种收益超过动作和推理开销。**RL 胜出的门槛**：对同动作空间的强规则/bandit 存在可重复的整数结果或证明时间改善，所有证明校验通过。若只减少迭代却总时间增加，或只在已看过三例有效，不满足门槛。

## 11. 分步落地，不一次扩大研究范围

1. **冻结环境与强规则基线**：复用 `RL/adaptive_v1` 的候选/认证接口；补特征、预算和完整 episode 日志；同步对接生产档位后处理。先证明新引擎 exact 模式与原生产链相同数学结果。
2. **检验动作可学性**：新开发集，同前缀受控动作比较；先规则与 bandit。已知旧四策略结果不足以决定 PPO 有效。
3. **小规模 RL**：小网络、少动作、在线 PPO，按实例族划分；先全部安全回归，再扩大规模。
4. **锁定最终算法并比较**：独立测试、消融、总预算公平实验，最终再与 Compact 对照。

后续第二个独立研究点是资源档位查询选择：当 CG 已有可用界而整数 Gap 未闭合时，学习优先精确求解哪个 (line,h,r) 档位及投入时间。档位 DP 的 optimistic/pessimistic 界保持原样。该阶段需要保留未解决档位和公平访问的确定性后备规则；第一版不与候选控制联合训练，以便解释收益。

如果主要困难始终是单个原价 PP 的长尾，考虑学习辅助大邻域/变量固定候选 + 无固定原问题认证，或传统定价求解技术。任何变量固定结果都只提供候选，不能代替原域最优性证明。
